# 本地笔记与正文注释

应用中的用户笔记与正文脚注是两套独立数据。正文脚注随内容资源发布，保持只读；用户笔记只保存在本机 `reader.db`，不会上传，也不依赖账号。

## 注释类型与文字选择

正文自带脚注属于内容资源的一部分，阅读时以只读方式展示；使用者添加的笔记分为纯高亮和带文字的批注，另有独立的书签。阅读器支持在正文中自由选择字符、字或词，系统选择菜单可以直接复制选区，也可以通过“高亮/批注”保存用户笔记。为保持现有段落锚点模型，高亮和批注的保存范围限定在同一段正文内。

## 精确笔记锚点

长按正文后，阅读器进入系统文字选择，读者可以拖动两端手柄自由调整字、词或字符范围；系统选择菜单提供复制，选择“高亮/批注”后可以保存用户笔记。笔记保存：

- 作品与章节稳定 ID；
- 原段落序号；
- 摘录在段落中的字符范围；
- 段落 SHA-256 指纹；
- 摘录前后各最多 32 个字符的上下文；
- 创建与更新时间。

正文版本变化后，阅读器依次尝试原位置精确匹配、同章摘录搜索和上下文评分。能够找回时更新本地锚点；无法确认时回退到原段落，并在书架中标记为段落级定位。

## 数据库与迁移

`reader.db`（`ReaderDatabase`，基于 `SQLiteOpenHelper`）当前版本为 6，除 `notes` 外还包含 `progress`、`chapter_progress`、`bookmarks`、`note_tags`、`reading_sessions`、`metadata` 以及全文检索表 `content_fts`（FTS4，`unicode61` 分词）。

升级在 `SQLiteOpenHelper` 的事务内按版本逐级执行：

- v2：新增 `chapter_progress`（章节级进度）；
- v3：重建 `notes` 表，完整复制旧笔记并增加精确锚点字段（字符范围、段落指纹、前后文、`anchor_state`），新表允许同一段落保存多条不同摘录笔记；
- v4：`progress` 与 `chapter_progress` 增加 `character_offset`、`completed`；
- v5：`notes` 增加 `note_kind`、`highlight_color`、`pinned`，并新增 `note_tags` 与 `reading_sessions`；
- v6：确保 `bookmarks` 表存在并补充 `character_offset`。

升级均在单一事务内完成，任一步失败即回滚，不会留下半迁移状态。

## 本地边界

笔记、阅读进度、书签和排版偏好只保存在本机应用数据中。应用不提供账号、同步、文件导入、文件导出、系统云备份或设备迁移；卸载应用或在系统设置中清除应用数据会一并删除这些本地记录。
